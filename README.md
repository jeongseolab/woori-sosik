# Tier.gg — 내 챔피언만으로 만드는 티어표

FastAPI 로 만든 롤 전적 서비스. 데이터는 OP.GG 가 공개한 MCP 서버에서 받는다.

- **나만의 티어표** — 최근 20판(솔로랭크·자유랭크·일반)에서 고른 챔피언을
  내 승률·KDA·판수와 내 티어 구간의 메타로 줄 세운다. OP 는 딱 한 명, 나머지는 1~5티어에 나눈다.
- **그룹방** — 방을 만들면 6글자 초대 코드가 나온다. 들어온 친구들끼리
  랭크·승률·KDA·분당 CS·OP 챔피언을 나란히 비교하고, 서로의 티어표를 본다.
- **듀오 궁합** — 두 사람의 경기에서 같은 판을 찾아 같이 할 때 승률,
  평소 승률, 잘 맞은 챔피언 조합, 맞대결 전적을 정리한다.
- **주간 랭킹** — 그룹방에서 이번 주(월요일 0시, 한국 시각부터) 종합 순위를 보여 준다.
  플레이 점수 50% + 승률 25% + KDA 25%, 셋 다 50점이 보통인 잣대로 바꿔 섞음. 이번 주 3판 이상.
  스킬샷 피하기 순위는 그룹방의 "무빙 순위" 탭에 따로 있다.
- **연습장: 스킬샷 피하기** — 사방에서 날아오는 논타깃 스킬을 피해 버티는 게임.
  노멀 모드와, 스킬의 CC(기절·속박·매혹·공중에 뜸·둔화) 를 그대로 당하는 하드 모드가 있다.
  그룹방 "무빙 순위" 탭에 모드별(노멀·하드) 최고 기록 순위가 나오고, 거기서 바로 도전하러 갈 수 있다.
  연습장의 "무빙 순위" 버튼은 마지막으로 본 방의 무빙 순위 탭으로 바로 간다.

## 스킬샷 피하기 (`static/dodge.js`)

서버 없이 화면 코드만으로 돈다. `index.html` 이 처음부터 같이 받아 두므로 누르면 바로 뜬다.

롤 인터페이스를 흉내 낸 오프라인 연습 모드 느낌으로 만든다.
- 아래 가운데 HUD: 내 챔피언 초상화(시작 창에서 고른 챔피언, 고르지 않았으면 티어표의 OP 챔피언, 없으면 이즈리얼)와 레벨, 스킬 네 칸(내 챔피언의 Q W E R
  아이콘, CommunityDragon. 키는 마우스 방식 Q W E R, WASD 방식 Mb2(우클릭)·Shift·E·R. 이동기 칸만 켜지고 나머지는 어둡게), 소환사 주문 두 칸(쿨타임이
  시계 방향으로 걷힌다), 세 칸으로 나뉜 체력(1500, 한 번 맞을 때 500). 위 가운데 시계, 오른쪽 위 피한 수·맞은 수,
  오른쪽 아래 미니맵(휴대폰은 숨김). 아래 HUD 가 경기장을 가리지 않게 그만큼 아래를 비워 둔다
- 머리 위 체력바: 나는 초록(레벨·이름), 적은 빨강(챔피언 이름). 맞으면 피해 숫자가 떠오른다
- 안내 문구: 시작할 때 "소환사의 협곡에 오신 것을 환영합니다", 30초마다 생존, 피한 수 20·40·60·80 에
  롤의 연속 처치 순서대로 "학살 중입니다!" → "미쳐 날뛰고 있습니다!" → "도저히 막을 수 없습니다!" → "전설의 출현!",
  한 칸 남으면 "체력이 낮습니다"(가장자리가 붉게 숨 쉰다),
  죽으면 화면이 회색으로 바뀌고 "처치당했습니다" 뒤에 결과 창
- 시작 전에 내 챔피언을 고를 수 있다. 목록은 이동기와 그 3D 동작이 다 들어간 40명(`MOBILITY`)뿐이고,
  맨 앞 "OP" 칸은 티어표의 OP 챔피언으로 되돌린다. 고른 챔피언은 브라우저에 기억하고, 티어표가 늦게 와도 덮어쓰지 않는다.
  처음 보는 챔피언의 3D 모델은 고를 때 로딩 화면을 띄우고 받는다
- 시작 전에 이동 방식과 주문 배치를 고른다(브라우저에 기억, 결과 창의 "조작 바꾸기" 로 다시 고름).
  마우스 클릭이면 우클릭 이동에 주문 키 D/F(WASD 이동은 꺼짐), WASD 면 키보드 이동에 주문 키 V/F
  (마우스 클릭 이동은 꺼지고 커서는 점멸 방향만). 휴대폰 터치 이동은 늘 된다
- 내 챔피언의 이동기: 이동기가 있는 40명(`dodge.js` 의 `MOBILITY`, 3D 동작은 `tools/champ_models.py` 의 같은 목록)은
  그 스킬 칸 하나를 쓴다. 순간이동(이즈리얼 E·카사딘 R·샤코 Q·조이 R, 조이는 1초 뒤 제자리로)과 돌진(루시안 E·베인 Q …),
  커서 반대쪽으로 뛰기(케이틀린 E·아칼리 E), 그동안 스킬이 통과(피즈 E), 10초 안에 세 번(아리 R).
  거리·돌진 속도는 롤 클라이언트 데이터(CommunityDragon 의 챔피언 bin: DashSpeed·DashDistance·castRangeDisplayOverride 등)이고,
  데이터에 없는 값(챔피언 스크립트 안의 돌진 속도 등)은 표에 `src: 추정` 으로 적었다(위키와 대조할 것).
  쿨타임은 롤 최대 레벨 값을 4~20초 안으로 맞춘다(궁극기 100초는 20초, 벨베스 Q 1초는 4초). 이동 불가 CC 중과 돌진 중에는 못 쓴다.
  이 규칙이 생겨 게임 버전 7(순위는 새 버전 기록부터)
- 소환사 주문: 점멸(커서 쪽으로 400, 커서를 모르면 가던 방향), 유체화(3초 동안 이동 속도 +40%).
  휴대폰은 HUD 의 칸을 누른다.
  아이콘과 실제 쿨타임(300초·240초) 은 롤 데이터, 점멸 거리·유체화 이속은 롤 위키. 쿨타임(15·20초) 과
  유체화 지속 시간은 이 게임에 맞게 줄였다.
  주문은 롤 클라이언트처럼 고른다: 시작 창의 주문 칸(D·F 또는 V·F)을 누르면 그 칸 위에 점멸·유체화·정화가 뜨고,
  고르면 그 칸이 바뀐다. 다른 칸에 있는 주문을 고르면 두 칸이 서로 바뀐다(목록에서 어둡게 보인다).
  마우스를 올리면 이름·쿨타임·설명이 나온다. 모드마다 따로 기억한다(처음엔 노멀 유체화·점멸, 하드 정화·점멸).
  정화는 아래 "하드 모드" 참고
- 레벨은 8초마다 하나(18까지). 효과음은 끌 수 있고, 위쪽 슬라이더로 볼륨(0~100%, 처음 70%)을 맞춘다.
  둘 다 브라우저에 기억한다. 모든 소리가 마스터 볼륨 하나를 거쳐서 나는 중인 소리도 바로 바뀌고, 슬라이더를 놓으면 점멸 소리로 크기를 들려 준다

### 롤 그림·소리 (`static/dodge/`)

- `ground.jpg`: 소환사의 협곡 미드 라인 바닥 텍스처(`maps/kitpieces/srx/base/textures/terrain_midlane_ground_a.png`)
  를 경기장 비율(1400:900) 로 자른 것. 원근에 맞게 가로 띠로 깔고, 스킬 빛이 잘 보이게 살짝 어둡게 덮는다
- `fx.webp`: 스킬 파티클 텍스처 43장을 한 장으로 묶은 것. 롤 클라이언트의 `characters/<챔피언>/skins/base/particles/*.png`
  (CommunityDragon 이 푼 것) 에서 스킬마다 골랐다(모르가나 Q 구체·사슬, 아리 하트, 레오나 검, 이즈리얼 Q 꼬리, 카서스 Q 고리,
  브랜드 W 균열, 베이가 E 벽, 진 W 경고선 등). 더하기 합성 기준으로 빛의 양을 알파로 바꿔 두었고, 흰 텍스처는 그릴 때
  스킬 색을 곱해 입힌다(`spr`). 자리 표는 `dodge.js` 의 `FX_MAP`, 스킬별 쓰임은 `MISSILE_ART`·`ZONE_ART`·`BEAM_ART`
  - 바닥에 까는 것(장판·그을린 자리·감옥 바닥)은 원근에 맞춰 평행사변형으로 편다(`floorSprite`).
    긴 띠(레이저)는 150 유닛씩 잘라 조각마다 원근 그대로의 네 귀퉁이를 반복 무늬로 칠한다(`floorStrip`. 이음매 줄이 안 생긴다)
  - 장판 텍스처는 텍스처 안 고리의 반지름 비율(`fit`)로 크기를 맞춰 판정 원과 겹치게 하고, 판정 원은 가는 선으로 한 번 더 긋는다
  - 베이가 W 는 하늘에서 암흑 물질이 떨어지고, 초가스 Q 는 터질 때 가시가 솟고, 베이가 E 는 테두리를 따라 보랏빛 벽이 선다
- `sfx/*.ogg`: 롤 위키(wiki.leagueoflegends.com) 에 올라온 소리. 점멸·유체화, 아나운서(환영합니다, 연속 처치 4단계,
  "You have been slain"), 위키에 기본 스킨 효과음이 있는 스킬(럭스 Q·R, 베이가 Q·W·E, 초가스 Q) 만 진짜 소리다.
  나머지 스킬은 WebAudio 합성음(투사체는 바람 소리, 장판은 터지는 소리). 연습장에 들어오면 미리 받아 풀어 둔다
- 그림·소리 파일을 못 받거나 못 푸는 브라우저(오프라인, ogg 를 못 푸는 구형 사파리)에서는 예전처럼 직접 그린 그림·합성음으로 돈다
- 그림·소리의 저작권은 Riot Games 에 있다. 이 사이트는 Riot Games 의 보증을 받지 않은 비영리 팬 프로젝트다
  (Riot 의 "Legal Jibber Jabber" 팬 콘텐츠 정책)

화면은 유사 3D 다. 판정과 움직임은 모두 바닥(2D) 에서 하고, 그릴 때만 롤 기본 카메라처럼 56° 비스듬히 내려다보는
원근으로 옮긴다(`proj`). 우클릭한 화면 위치는 거꾸로 바닥 좌표로 되돌린다(`unproj`).
캐릭터·적 초상화·투사체는 화면에서 똑바로 세우고(`upright`), 감옥 창살·빛기둥은 원근을 따른다.
투사체는 공중에 떠서 날지만 바닥에 보이는 그림자 원이 실제 판정이다. 내 발밑 초록 링(65) 과 이 원이 겹치면 맞는다.
투사체의 밝게 꽉 찬 부분은 판정 크기와 같고, 바깥 빛번짐은 옅게만 둔다.
생김새는 스킬마다 다르다(`look`): 자이라 E 는 바닥을 기는 덩굴, 블리츠·쓰레쉬 Q 는 사슬 달린 갈고리, 니달리 Q 는 창,
애쉬 R 은 얼음 화살, 징크스 W 는 전격, 레오나 E 는 칼날, 아리 E 는 하트, 이즈리얼 Q 는 광탄, 브랜드 Q 는 불티 날리는 화염구.
판정은 모두 머리 쪽 원 하나다. 제라스 W·레오나 R 은 데이터의 중심부(100·120) 를 안쪽 점선 원으로 보여 준다(맞는 범위는 바깥 원)
효과(빛나는 투사체와 꼬리, 장판이 터질 때 빛기둥·고리·파편, 레이저 섬광, 맞을 때 흔들림과 붉은 테두리) 는 그림일 뿐 판정과 상관없다.

- 거리·속도는 롤 게임 단위 그대로다. 내 챔피언은 판정 반지름 65(데이터에 따로 없는 챔피언의 기본값.
  블리츠·초가스는 80, 베이가는 55), 이동 속도 335(챔피언 기본 이동 속도 `baseMoveSpeed` 325~345 의 가운데 값)
- 어떤 스킬이 나올지: 그때까지 열린 스킬(`from` 초부터) 중에서 똑같은 확률로 고른다. 그래서 초반엔 5개가 20% 씩,
  50초 뒤엔 24개가 4% 씩이다. 가끔 스킬(애쉬 R·럭스 R) 은 둘을 합쳐 3%. 감옥은 한 번에 하나만
- 목숨 3개. 3번 맞으면 끝이고 버틴 시간이 기록이다. 맞은 뒤 1초는 무적(스킬 두 개에 한꺼번에 목숨 둘을 잃지 않게).
  스킬 하나는 한 번만 때린다(맞힌 투사체는 사라지고, 감옥은 한 번 스턴하면 끝)
- 스킬 26개, 네 종류:
  - 투사체 15개: 모르가나 Q, 럭스 Q, 자이라 E, 니달리 Q, 브랜드 Q, 아리 E, 벨코즈 Q, 제라스 E,
    이즈리얼 Q, 레오나 E, 베이가 Q, 블리츠 Q, 쓰레쉬 Q, 징크스 W, 애쉬 R(점점 빨라짐).
    벨코즈 Q 는 내 옆을 지나갈 때(원래 길로는 빗나갈 때) 또는 사거리 끝에서 양옆 직각으로 갈라진다.
    갈라지기 0.25초 전(`SplitTelegraphTime`)에 구슬이 부풀며 번쩍인다. 롤처럼 갈라질 경로는 미리 안 보여 준다.
    갈라진 것은 속도 2100·반지름 45·사거리 1100(`VelkozQMissileSplit`)
  - 지연 장판 8개: 카서스 Q, 브랜드 W, 초가스 Q, 베이가 W, 신드라 Q, 제라스 W, 벨코즈 E, 레오나 R.
    바닥에 원이 보이고 다 차면 터진다
  - 지연 레이저 2개: 진 W, 럭스 R. 시전하는 동안 가는 선이 보이고 끝나는 순간 선 전체를 친다
  - 감옥 1개: 베이가 E. 테두리에 닿으면 맞는다
- 스킬 값의 출처: 롤 클라이언트의 챔피언 데이터 파일(CommunityDragon 의 `characters/*.bin.json`, 16.19).
  속도 `missileSpeed`, 반지름 `mLineWidth`, 사거리 `castRange`, 시전 시간 `mCastTime`(없으면 `spellCastTime`),
  장판 반지름 `castRadius`, 지연 시간 `CageDelay`·`ImpactDelay`·`DamageDelay` 등.
  데이터 파일에 없는 값(초가스·브랜드·카서스·신드라·레오나 장판의 지연 시간, 초가스 Q·럭스 R 시전 시간,
  베이가 E 지속 시간)은 롤 위키 값이다. `dodge.js` 의 표에 스킬마다 `src` 로 적어 두었다.
  신드라 Q 는 위키가 "누르고 0.6초 뒤 나타난다" 로 적어서 시전 시간을 0 으로 두었다(데이터의 spellCastTime 은 0.375)
- 표의 값은 데이터 파일에서 같은 항목을 읽어 한 줄씩 대조해 확인했다(16.19 기준, 108 항목 중 데이터에 있는 101 개 가운데 100 개가 같음.
  다른 1개는 위의 신드라 Q)
- 쏘는 사람은 롤에서처럼 사거리 끝 가까이(사거리의 60~100%)에서 쏜다
- 장판은 수치는 그대로 두고 찍는 자리만 사람처럼 한다. 정중앙에 찍으면 브랜드 W(반지름 240, 0.627초) 같은 건
  표시를 보자마자 달려도 못 나간다. 그래서 표시가 뜬 뒤 0.25초(반응 시간, `REACT`) 늦게 움직여도 딱 빠져나갈 만큼만
  내 자리에서 비껴 찍는다. 원은 여전히 몸에 걸쳐서 가만히 있으면 맞는다
- 스킬 판정과 내 판정 원이 겹치면 맞는다. 빠른 투사체가 한 프레임에 뛰어넘지 않게 1/240초씩 나눠 움직인다
- 규칙이 바뀌면 `dodge.js` 의 `VERSION` 과 `ranking.py` 의 `DODGE_VERSION` 을 같이 올린다.
  순위는 같은 버전의 기록끼리만 매기고, 예전 화면에서 온 기록은 받지 않는다
- 조작: 우클릭(누른 채 끌면 따라감), WASD·방향키, 휴대폰은 터치.
  WASD 는 `e.code` 로 읽어서 한글 입력 상태에서도 된다
- 기록: 판을 시작할 때 서버가 표를 끊고(`/api/dodge/start`), 끝났을 때 그 사이에 흐른 시간보다
  긴 기록은 받지 않는다(`ranking.py`). 1초 미만 판은 저장하지 않는다
- 모드: 기록에 `mode`(normal | hard) 를 같이 보내고 `dodge_runs.mode` 에 적는다. 예전 판(비어 있음) 은 노멀로 친다.
  순위·내 기록은 모드별로 따로다. `/api/dodge/me` 와 `/api/rooms/{id}/dodge` 는 예전 자리에 노멀을, `hard` 에 하드를 준다.
  노멀 규칙은 그대로라 `VERSION` 은 6 그대로다

### 하드 모드

무적이 없고(맞은 뒤 1초 무적 없음), 맞은 스킬의 CC 를 예외 없이 당한다. 목숨은 똑같이 3개.
CC 는 `dodge.js` 의 `applyCC` 에 스킬마다 적었다. 값은 롤 클라이언트 데이터(CommunityDragon 의 `*.bin.json`,
16.19 의 `DataValues`), 데이터에 없는 것은 롤 위키·나무위키. 스킬 레벨은 내 레벨 3마다 오른다(13레벨부터 5).

| 스킬 | CC |
|---|---|
| 모르가나 Q · 럭스 Q · 자이라 E | 속박 2~3초 · 2초 · 1~2초 |
| 레오나 E | 속박 0.5초, 레오나가 내 뒤 225 로 돌진 |
| 진 W | 표식(맞은 지 4초 안) 이 있으면 속박 1.25~2.25초 |

| 베이가 E | 테두리에 닿으면 기절 1.5~2.5초 |
| 제라스 E · 애쉬 R | 날아간 거리에 비례해 기절 0.75~2.25초 · 1~3.5초 |
| 브랜드 Q | 불길(브랜드 스킬에 맞고 4초) 이 있으면 기절 1.75초. 브랜드 Q·W 가 불길을 건다 |
| 블리츠크랭크 Q | 기절 0.65초 + 블리츠 앞 75 까지 끌려간다(공중에 뜸) |
| 쓰레쉬 Q | 기절 1.5초 + 공중에 뜸 0.4초, 기절 중 0.1·0.7초에 쓰레쉬 쪽으로 끌려간다 |
| 초가스 Q · 벨코즈 E | 공중에 뜸 1초 뒤 둔화 60% 1.5초 · 공중에 뜸 0.75초 |
| 레오나 R | 둔화 80% 1.75초, 중심부는 기절 1.75초도 |
| 제라스 W | 둔화 25% 2.5초, 중심부는 60~80% 에서 25% 로 줄어든다 |
| 벨코즈 Q · 징크스 W | 둔화 70% 가 1~2.6초에 걸쳐 0 으로 · 둔화 40~80% 2초 |

롤 위키(wiki.leagueoflegends.com) 의 스킬 데이터와 군중 제어 문서로 한 번 더 대조했다.
추정값(클라이언트 데이터·롤 위키 모두 숫자가 없음): 애쉬 R 이 최대 기절이 되는 거리 1500,
쓰레쉬 Q 한 번에 끌리는 거리 100(위키는 "짧은 거리"), 블리츠 Q 에 끌려가는 속도 1800. 코드에 "추정" 이라고 적어 두었다.

CC 규칙(나무위키 "군중제어기"):
- 기절·속박·매혹·공중에 뜸 중에는 점멸을 못 쓴다(HUD 칸이 잠긴다). 유체화·정화는 쓸 수 있다. 이동 명령은 끊긴다
- 둔화는 가장 센 것 하나만, 이동 속도는 110 아래로 안 내려간다(매혹의 둔화는 예외)
- 정화(쿨타임 20초, 실제 240초): 공중에 뜸을 뺀 CC 를 풀고(쓰레쉬 사슬도 끊긴다) 3초 동안 강인함 75%
  (그 사이 새 CC 가 1/4 로 짧아진다. 단 강인함으로는 0.5초 밑으로 안 줄어든다). 공중에 뜸은 강인함·정화가 안 통한다.
  초가스 Q 의 공중에 뜸 뒤 둔화는 정화로 막지 못한다(위키)
- 롤처럼 걸린 CC 이름이 머리 위 이름 자리에 뜨고 체력바 아래 선이 남은 시간만큼 줄어든다.
  기절은 머리 위 별, 속박은 발밑 마법진과 몸을 묶는 고리, 매혹은 하트, 공중에 뜨면 초상화가 떠오르고, 둔화는 발밑 소용돌이와 발자국

### 효과층 (`static/dodge-gl.js`)

WebGL 로 그리는 효과층. 게임 화면은 지금처럼 Canvas 2D 로 바닥(bg) 과 선 것들(fg) 두 장에 그리고, 효과층이
둘을 텍스처로 받아 합치면서 2D 로는 못 하는 것을 더한다. Riot 의 VFX 스타일 가이드(판정이 먼저 읽혀야 한다,
주·보조 형태, 예고 → 터짐 → 흩어짐) 와 실시간 VFX 기법을 따랐다.
- 파티클·리본 꼬리: 쿼드 수천 개를 한 번에 그린다. 바닥 층은 bg 와 fg 사이, 공중 층은 fg 위.
  빛(더하기)과 연기(반투명)를 미리 곱한 알파 하나로 섞어 그리고, 노이즈 침식(dissolve) 으로 갉아먹히며 사라지게,
  노이즈 흐름으로 에너지가 일렁이게 한다. 모양 텍스처(빛 구슬·불티·고리·연기·별·하트·얼음 조각·잎·불꽃·빛기둥·
  사슬·소용돌이·마법진·햇살) 와 이어지는 노이즈는 처음에 코드로 만든다
- 스킬마다 `GFX` 표: 투사체의 빛·리본 꼬리·흘리는 파티클(모르가나 어둠 연기, 브랜드 불꽃·불티, 애쉬 얼음 조각,
  아리 하트, 럭스 별빛 등), 장판이 차오르는 마법진·에너지와 터질 때의 빛기둥·파편·연기·영혼·햇살, 레이저 빛줄기,
  시전 중 초상화로 빨려 드는 빛, 맞을 때·점멸·정화·CC 걸림 효과
- 충격파 왜곡(터진 자리에서 퍼지는 고리 모양 굴절, 원근에 맞게 눌린 타원), 빛 번짐(1/2·1/4·1/8 로 흐려 더함),
  맞을 때 색수차, 가장자리 어둡게, 맞음·낮은 체력의 붉은 테두리, 죽으면 회색, 화면 흔들림
- 캔버스에 그리는 초상화는 CORS 를 허용하는 CommunityDragon 챔피언 아이콘(`champion-icons/{id}.png`) 을 쓴다.
  CORS 없는 그림을 그리면 캔버스가 오염돼 WebGL 로 못 올린다. 이름 → ID 는 `champion-summary.json` 을 한 번 받는다
- WebGL 을 못 쓰거나 끊기면(캔버스 오염 포함) 2D 로 물러난다. 파티클은 2D 로 그대로 그리고 침식·왜곡·번짐만 빠진다

### 3D 챔피언 (`static/dodge/models/`, `tools/champ_models.py`)

실제 롤 챔피언 모델이 롤의 애니메이션으로 움직인다. 나는 움직이면 달리기, 멈추거나 CC 중이면 서 있기를 하며 가는 쪽을 보고,
적은 시전하는 동안 그 스킬의 실제 동작(Q·W·E·R → `spell1`~`spell4`)을 하며 노리는 쪽을 본다. 레오나 E 돌진은 달리기.
맞으면 흰빛, 유체화는 푸른빛이 돌고, 맞은 뒤 무적이면 깜빡인다. 체력바·CC 이름은 모델 머리 위에 뜬다.
모델이 없는 챔피언(목록에 없거나, 받는 중이거나, WebGL 이 없을 때)은 예전처럼 초상화로 그린다.

- 모델은 개발자 PC 에서 `tools/champ_models.py` 로 만든다. 롤이 설치된 PC 의 게임 파일(`Champions/<챔피언>.wad.client`)에서
  모델(`.skn`)·뼈대(`.skl`)·애니메이션(`.anm` v3·v4·v5, 압축된 `canm`)을 꺼낸다. 뼈대·애니메이션은 CommunityDragon 에 없어서
  게임 파일이 있어야 한다. 텍스처는 CommunityDragon 이 PNG 로 풀어 둔 것을 512px webp 로 줄인다
- 애니메이션은 프레임마다(초당 15) 뼈의 스킨 행렬(전역 × 바인드 역행렬)로 미리 구워 float16 으로 담는다.
  어떤 클립을 쓸지는 챔피언의 애니메이션 그래프(`animations/skin0.bin.json`)에서 이름으로 찾고(서 있기 `Idle_Base`·`Idle1`…,
  달리기 `Run_Normal`·`Run`…, 스킬 `Spell1`…), 이어 붙이기·겹치기·고르기 클립과 해시로 가리킨 클립도 따라간다
- 화면은 효과층이 정점마다 뼈 행렬 네 개를 섞어(CPU) 그린다. 투영은 `dodge.js` 의 `proj` 와 같은 식을 셰이더에서 그대로 해서
  2D 로 그린 바닥·판정 원과 정확히 겹친다. 깊이 버퍼로 모델끼리 앞뒤를 가린다. 롤 모델은 앞이 +z, 오른쪽이 +x 다
- 체력바 높이는 머리 관절 높이 + 35(웅크린 체형은 정점 높이 85% 쪽)
- 지금 들어 있는 것: 모든 챔피언(173명). 합계 약 76MB, 챔피언 하나에 모델 300~700KB · 텍스처 30KB 안팎.
  모두 서 있기·달리기, 연습장에서 스킬을 쓰는 19명은 그 스킬 동작까지.
  나중에 내 챔피언 스킬로 쓰려고, 바로 쓰는 이동기(돌진·순간이동, 대상 지정·차징·패시브 제외)가 있는 40명은
  그 스킬 동작도 넣었다(`tools/champ_models.py` 의 `MOBILITY`, `--mobility` 로 다시 만든다). 새 챔피언이 나오면 다시 만든다.
  클립은 이어 붙이기·겹치기·고르기 말고도 조건(귀환 중인지, 이동 속도) · 방향(앞·뒤·옆) 으로 나뉜 것을 따라가 보통 앞으로 달리기를 고른다.
  텍스처가 재질에만 있는 챔피언(이블린) 은 스킨 폴더에서 기본 색 텍스처를 찾는다.
  부품마다 텍스처가 다른 챔피언(모르가나 날개, 아트록스 검, 무기 등) 은 부품 텍스처들을 한 장(아틀라스) 에 칸으로 붙이고
  그 부품의 UV 를 자기 칸으로 옮긴다(텍스처 2장이면 1024×512, 3~4장이면 1024×1024, 더 많으면 칸을 256 으로).
- 모델은 연습장 화면이 뜨자마자 스킬 쓰는 챔피언 것을 미리 받는다(처음 나올 때 받으면 일찍 나오는 모르가나·초가스 등이
  다 받기 전까지 초상화로 보였다). 받다가 실패하면 3초 뒤 다시 받는다. 다시 만들려면:
  ```
  pip install xxhash zstandard numpy pillow
  python tools/champ_models.py ahri jinx        # 고른 챔피언
  python tools/champ_models.py --all            # 모든 챔피언
  python tools/champ_models.py --game "D:/Riot Games/League of Legends"
  ```

## 로그인

Riot ID(이름#태그) + 이 사이트 전용 비밀번호. 가입할 때 OP.GG 에서 그 계정이
정말 있는지 확인한다. 한국 서버만 된다.

Riot 공식 로그인(RSO)은 Riot 의 정식(프로덕션) 앱 승인을 받아야 쓸 수 있다.
승인을 받으면 `auth.py` 의 `check_login` 자리만 바꾸면 된다.

### 닉네임(태그)을 바꾸면

계정은 puuid(라이엇 계정 고유 번호, 이름을 바꿔도 그대로) 로 묶여 있다.

- **새 닉네임으로 로그인**하면 OP.GG 에서 새 닉네임의 puuid 를 받아, 그 puuid 계정의 비밀번호와 맞춰 본다.
  맞으면 "옛 닉 → 새 닉, 이름이 변경되었습니까?" 를 묻고, 예를 누르면 계정 이름만 바꾼다. 전적과 그룹방은 그대로다
- 티어표·그룹방·듀오는 부를 때마다 저장된 puuid 와 OP.GG 의 puuid 를 맞춰 본다.
  다르면(누가 옛 닉네임을 가져갔으면) 남의 전적 대신 "닉네임이 바뀐 것 같아요" 를 보여 준다
- 대소문자만 바뀐 경우는 로그인할 때 OP.GG 표기대로 조용히 고친다

## 점수 매기는 법 (`perf.py`, `tierlist.py`)

재료는 최근 20판(솔로랭크·자유랭크·일반). 칼바람·아레나, 5분 안에 끝난 다시하기 판은 뺀다.
20판 승률은 팀운에 크게 흔들려서, 중심은 **판마다 얼마나 잘했나(플레이 점수)** 다.

### 플레이 점수 (한 판, 0~100, 50 = 보통)

지표마다 **그 라인의 보통 수준**과 견준다. 기준값은 에메랄드 평균 어림값이고,
그 판의 평균 티어에 맞춰 늘리고 줄인다(브론즈 판이면 CS 기준이 낮아진다).

| 영역 | 보는 것 |
|---|---|
| 전투 | KDA, 킬 관여율 |
| 성장 | 분당 CS, 팀 골드 중 내 몫 (서폿은 골드 몫만) |
| 스노우볼 | 14분 무렵 OP.GG 평점, 최다 연속 킬 |
| 딜 | 분당 챔피언 피해량 |
| 시야 | 분당 와드 설치 + 제어 와드 |
| OP.GG 평점 | OP.GG 가 매긴 그 판 평점(0~10) |

라인마다 비중이 다르다. 서폿은 시야·전투, 원딜은 딜·성장, 정글은 전투·스노우볼을 크게 본다.

### 챔피언 점수

점수 = 보정 플레이 점수 + 승률 보정 + 판수 가산 + 메타 가산

- **보정 플레이 점수**: 그 챔피언 판들의 플레이 점수 평균. 보통(50점) 판을 2판 섞어서
  1판만 잘한 챔피언이 꾸준히 잘한 챔피언을 앞지르지 않게 한다
- **승률 보정**: 50% 에서 10%p 벗어날 때마다 1점, 최대 ±5점
- **판수 가산**: 한 판 더 고를 때마다 0.75점 (8판까지)
- **메타 가산**: 내 티어 구간 OP.GG 챔피언 티어. 3티어 기준 한 칸에 1.5점

**실제 티어**는 솔로랭크 → 자유랭크 → (언랭이면) 최근 판들의 평균 티어 순서로 정한다.
공식 티어(메타 가산)와 플레이 점수 기준값 모두 이 티어 구간에 맞춘다.
그 구간의 공식 티어를 못 받으면 전체 구간 것을 쓰고, 화면에 "전체 구간" 이라고 적는다.

OP 는 1등 딱 한 명, 나머지는 점수 순서대로 1~5티어에 나눈다.

## 알아 둘 것

- 화면(`app.js` 의 `load`)은 한 번 받은 것을 기억해 두고, 화면을 옮겨도 다시 받지 않는다.
  로그인하면 내 티어표와 모든 방의 카드·주간 랭킹·무빙 순위를 뒤에서 미리 받아 둔다.
  새로 받는 건 새로고침하거나 "최신 전적으로" 버튼을 누를 때, 내가 바꾼 것(방 만들기·들어가기·나가기,
  스킬샷 기록)이 있을 때, 그리고 아래처럼 바뀐 게 보일 때뿐이다
- 바뀐 것만 다시 받기: 1분마다 `/api/stamp`(`changes.py`, DB 만 읽음)로 방 사람·무빙 기록·쌓인 경기 수의
  지문을 보고, 달라진 항목의 데이터만 다시 받는다. 5분마다는 받아 둔 티어표·방 카드·듀오를 다시 받아 새 판을 잡는다
  (서버가 OP.GG 대답을 10분 들고 있어서 OP.GG 를 매번 부르지는 않는다). 다른 탭에 있다 돌아오면 바로 한 번 본다.
  지금 보는 화면의 것이 바뀌었으면 로딩 없이 다시 그리고 알려 준다. 게임 중이거나 팝업을 보는 중이면 건드리지 않는다
- OP.GG MCP 서버는 원래 AI 도구용이다. 키는 없지만 너무 자주 부르지 않게
  받은 것을 `api_cache` 표에 잠깐 들고 있는다(전적 10분, 챔피언 통계 12시간).
- 처음 티어표를 만들 때는 챔피언마다 통계를 물어서 15초쯤 걸린다. 그다음부터는 바로 나온다.
- OP.GG 는 모드를 가리지 않고 한 번에 최근 20판만 알려 주고, 더 이전 판을 달라고 할 방법이 없다.
  그래서 받을 때마다 `match_rows` 에 쌓아 두고, 쌓인 것에서 협곡 판만 최근 20판을 꺼낸다.
  칼바람을 많이 하는 사람은 처음엔 20판이 안 찰 수 있고, 볼수록 채워진다.
  듀오 궁합도 쌓인 판 전부에서 같이 한 판을 찾으므로 자주 볼수록 정확해진다.

## 내 컴퓨터에서 돌리기

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

`http://127.0.0.1:8000` 으로 접속. 데이터는 `mytier.db` 파일에 쌓인다.

## 올리는 법 (Render, 무료)

1. <https://render.com> → **New** → **Web Service** → 이 저장소 고르기.
   `render.yaml` 이 있으니 설정은 자동으로 잡힌다.
2. **Environment** 에 `DATABASE_URL` 을 넣는다. 무료 요금제는 서버가 잠들었다 깨면
   파일이 날아가므로, 계정과 방은 바깥 Postgres(<https://neon.com> 무료)에 둔다.
3. Deploy.

무료 요금제는 15분 안 쓰면 잠들고, 다시 깨는 데 30초쯤 걸린다.
그래서 `.github/workflows/keepalive.yml` 이 10분마다 `/api/health` 를 불러 깨워 둔다.
- 무료 750시간/월은 서비스 하나를 계속 켜 두는 만큼(약 720시간)이다. 깨워 둘 서비스는 하나만 둔다
- 저장소에 60일 동안 변경이 없으면 GitHub 이 예약 실행을 멈춘다. 그땐 Actions 탭에서 다시 켠다

DB 는 연결을 몇 개 열어 두고 돌려 쓴다(`database.py` 의 연결 풀).
4분 넘게 안 쓴 연결은 닫아서 Neon 이 잠들 수 있게 한다.

### 주소(도메인)

- Render 주소(`이름.onrender.com`)는 서비스를 **만들 때** 이름으로 정해지고, 나중에 바꿀 수 없다.
  `render.yaml` 의 이름은 `tier-gg` 라서 새로 만들면 `tier-gg.onrender.com` 이 된다.
  예전 `woori-sosik.onrender.com` 서비스는 이름만 바꿔도 주소가 그대로다.
- `tier.gg` 같은 진짜 도메인은 따로 사서 Render 서비스의 **Settings → Custom Domains** 에 붙인다.
