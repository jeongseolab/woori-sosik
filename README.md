# Tier.gg — 내 챔피언만으로 만드는 티어표

FastAPI 로 만든 롤 전적 서비스. 데이터는 OP.GG 가 공개한 MCP 서버에서 받는다.

- **나만의 티어표** — 최근 20판(솔로랭크·자유랭크·일반)에서 고른 챔피언을
  내 승률·KDA·판수와 내 티어 구간의 메타로 줄 세운다. OP 는 딱 한 명, 나머지는 1~5티어에 나눈다.
- **그룹방** — 방을 만들면 6글자 초대 코드가 나온다. 들어온 친구들끼리
  랭크·승률·KDA·분당 CS·OP 챔피언을 나란히 비교하고, 서로의 티어표를 본다.
- **듀오 궁합** — 두 사람의 경기에서 같은 판을 찾아 같이 할 때 승률,
  평소 승률, 잘 맞은 챔피언 조합, 맞대결 전적을 정리한다.

## 로그인

Riot ID(이름#태그) + 이 사이트 전용 비밀번호. 가입할 때 OP.GG 에서 그 계정이
정말 있는지 확인한다. 한국 서버만 된다.

Riot 공식 로그인(RSO)은 Riot 의 정식(프로덕션) 앱 승인을 받아야 쓸 수 있다.
승인을 받으면 `auth.py` 의 `check_login` 자리만 바꾸면 된다.

## 점수 매기는 법 (`perf.py`, `tierlist.py`)

재료는 최근 20판(솔로랭크·자유랭크·일반). 칼바람·아레나, 5분 안에 끝난 다시하기 판은 뺀다.
20판 승률은 팀운에 크게 흔들려서, 중심은 **판마다 얼마나 잘했나(플레이 점수)** 다.

### 플레이 점수 (한 판, 0~100, 50 = 보통)

지표마다 **그 라인의 보통 수준**과 견준다. 기준값은 에메랄드 평균 어림값이고,
그 판의 평균 티어에 맞춰 늘리고 줄인다(브론즈 판이면 CS 기준이 낮아진다).

| 영역 | 보는 것 |
|---|---|
| 전투 | KDA, 킬 관여율 |
| 성장 | 분당 CS, 팀 골드 중 내 몫 (서폿은 골드 몫만) |
| 스노우볼 | 14분 무렵 OP.GG 평점, 최다 연속 킬 |
| 딜 | 분당 챔피언 피해량 |
| 시야 | 분당 와드 설치 + 제어 와드 |
| OP.GG 평점 | OP.GG 가 매긴 그 판 평점(0~10) |

라인마다 비중이 다르다. 서폿은 시야·전투, 원딜은 딜·성장, 정글은 전투·스노우볼을 크게 본다.

### 챔피언 점수

점수 = 보정 플레이 점수 + 승률 보정 + 판수 가산 + 메타 가산

- **보정 플레이 점수**: 그 챔피언 판들의 플레이 점수 평균. 보통(50점) 판을 2판 섞어서
  1판만 잘한 챔피언이 꾸준히 잘한 챔피언을 앞지르지 않게 한다
- **승률 보정**: 50% 에서 10%p 벗어날 때마다 1점, 최대 ±5점
- **판수 가산**: 한 판 더 고를 때마다 0.75점 (8판까지)
- **메타 가산**: 내 티어 구간 OP.GG 챔피언 티어. 3티어 기준 한 칸에 1.5점

**실제 티어**는 솔로랭크 → 자유랭크 → (언랭이면) 최근 판들의 평균 티어 순서로 정한다.
공식 티어(메타 가산)와 플레이 점수 기준값 모두 이 티어 구간에 맞춘다.
그 구간의 공식 티어를 못 받으면 전체 구간 것을 쓰고, 화면에 "전체 구간" 이라고 적는다.

OP 는 1등 딱 한 명, 나머지는 점수 순서대로 1~5티어에 나눈다.

## 알아 둘 것

- OP.GG MCP 서버는 원래 AI 도구용이다. 키는 없지만 너무 자주 부르지 않게
  받은 것을 `api_cache` 표에 잠깐 들고 있는다(전적 10분, 챔피언 통계 12시간).
- 처음 티어표를 만들 때는 챔피언마다 통계를 물어서 15초쯤 걸린다. 그다음부터는 바로 나온다.
- OP.GG 는 모드를 가리지 않고 한 번에 최근 20판만 알려 주고, 더 이전 판을 달라고 할 방법이 없다.
  그래서 받을 때마다 `match_rows` 에 쌓아 두고, 쌓인 것에서 협곡 판만 최근 20판을 꺼낸다.
  칼바람을 많이 하는 사람은 처음엔 20판이 안 찰 수 있고, 볼수록 채워진다.
  듀오 궁합도 쌓인 판 전부에서 같이 한 판을 찾으므로 자주 볼수록 정확해진다.

## 내 컴퓨터에서 돌리기

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

`http://127.0.0.1:8000` 으로 접속. 데이터는 `mytier.db` 파일에 쌓인다.

## 올리는 법 (Render, 무료)

1. <https://render.com> → **New** → **Web Service** → 이 저장소 고르기.
   `render.yaml` 이 있으니 설정은 자동으로 잡힌다.
2. **Environment** 에 `DATABASE_URL` 을 넣는다. 무료 요금제는 서버가 잠들었다 깨면
   파일이 날아가므로, 계정과 방은 바깥 Postgres(<https://neon.com> 무료)에 둔다.
3. Deploy.

무료 요금제는 15분 안 쓰면 잠들고, 다시 깨는 데 30초쯤 걸린다.
그래서 `.github/workflows/keepalive.yml` 이 10분마다 `/api/health` 를 불러 깨워 둔다.
- 무료 750시간/월은 서비스 하나를 계속 켜 두는 만큼(약 720시간)이다. 깨워 둘 서비스는 하나만 둔다
- 저장소에 60일 동안 변경이 없으면 GitHub 이 예약 실행을 멈춘다. 그땐 Actions 탭에서 다시 켠다

DB 는 연결을 몇 개 열어 두고 돌려 쓴다(`database.py` 의 연결 풀).
4분 넘게 안 쓴 연결은 닫아서 Neon 이 잠들 수 있게 한다.

### 주소(도메인)

- Render 주소(`이름.onrender.com`)는 서비스를 **만들 때** 이름으로 정해지고, 나중에 바꿀 수 없다.
  `render.yaml` 의 이름은 `tier-gg` 라서 새로 만들면 `tier-gg.onrender.com` 이 된다.
  예전 `woori-sosik.onrender.com` 서비스는 이름만 바꿔도 주소가 그대로다.
- `tier.gg` 같은 진짜 도메인은 따로 사서 Render 서비스의 **Settings → Custom Domains** 에 붙인다.
